Software engineering as we know it is about to change. Agentic coding is simply too convenient to ignore, and Claude Opus is genuinely good at it.

Writing code is becoming a commodity. What will matter is domain knowledge: understanding how complicated systems work, and how to put them together faster and more accurately than anyone else.

The most important skill, in my opinion, is taste. Making good decisions, designing software well, and always keeping the bigger picture in view.

## The one gap: memory

The biggest weakness of Claude Code today is memory. In short, it has none. It can grep and search your codebase, but it has to do that from scratch every session. An engineer who owns their work just *knows* where to look.

Retrieval doesn't close that gap. Context has to be loaded token by token, and RAG is still a bottleneck compared to a person who simply remembers. Our brains encode specific, local knowledge cheaply. A model has to burn enormous compute just to learn general skills, like how to write a C++ lambda, let alone how your particular codebase fits together.

## TL;DR

AI hasn't yet learned to pick up a specific human design on the fly. It knows the general rules of software, but it has no lasting sense of *your* code, so it re-reads and re-tokenizes it every time. For now, that's the edge engineers still have.
